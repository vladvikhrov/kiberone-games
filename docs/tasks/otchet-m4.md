# Отчёт по этапу М4: оценки по сети

Постановка: [`etap-m4.md`](etap-m4.md), к ней в конце добавлен раздел «Уточнения при выполнении». Дата: 04.11.2026. Проверено на Linux (Node 18.19, Electron 45.2.1): модульные тесты, тест-«взломщик» в сетевых пространствах на настоящих сервере и программе ученика, нагрузочный стенд. На Windows и на занятии не проверялось: задание для Влада — [`windows-m4.md`](windows-m4.md).

## Итог

Ребёнок ставит от 1 до 5 звёзд, оценка уходит на сервер тьютора, весь класс видит среднее, когда у режима 5 оценок и больше. Тьютор видит распределение по каждому режиму без перезапуска и сохраняет срез в файл. На диске тьютора только счётчики: адреса и времени голоса нет (проверено поиском метки, вариант с журналом её находит). Повтор с того же ноутбука в тот же день сервер не считает, даже если ребёнок удалил отметку у себя. Пока идёт игра, голос ждёт и уходит после закрытия. Без сервера голос ждёт в памяти и уходит, когда раздача снова включена. Голоса проходят за 14–27 мс, даже когда все слоты заняты и стоит предел 30 Мбит/с.

Две находки по дороге: после отправки звёзды гасли, и ребёнок не видел, что поставил (исправлено). Прежние поддельные серверы в тестах М2 и М3 падали на новом пути `/v1/ratings` (исправлены тесты, настоящий сервер отвечает 404).

## Что сделано

- `desktop/tutor/votes.js` (новый): разбор голоса, HMAC с солью дня в памяти, предел 50 000 отметок, счётчик `ratings.json` с атомарной записью, ответ `/v1/ratings`. Объект `guard` подменяет только стенд.
- `desktop/tutor/server.js`: `POST /v1/votes` (тело до 256 байт, таймаут 5 с, вне слотов и ведра), `GET /v1/ratings` с `ETag`, заголовок `X-K1-Day` у каталога и рейтинга.
- Программа тьютора: модуль голосов создаётся один раз на запуск (`desktop/tutor/index.js`), режимы игр в снимке каталога для сервера, панель «Оценки» с обновлением раз в 3 с и кнопкой «Сохранить срез» (канал `ratings.saveSnapshot`, системное окно сохранения).
- `shared/ratings.js`: ответ сервера с порогом `n < 5`, строгий разбор на стороне ученика, сводка для витрины.
- `desktop/school-net.js`: `post` по тем же правилам, что `get`; `X-K1-Day` только вида ГГГГ-ММ-ДД.
- `desktop/vitrina/net-source.js`: очередь голосов в памяти, отправка до загрузок, рейтинг с сервера в каждом цикле, дата тьютора. Сбой рейтинга загрузкам не мешает.
- `desktop/vitrina/api.js`, `store.js`: на настроенном ноутбуке только отметка дня, рейтинг и `votePending` из сети. Каналов по-прежнему 4.
- Витрина: «Спасибо! Оценка ушла тьютору» и «Отправлю тьютору, когда будет связь», звёзды после отправки остаются залитыми.
- Стенд: `redteam/net-run-m4.js` (К20а, К20б, К27, К28, Р2), `redteam/vote-client.js`, режим `net-vote` в `net-harness.js`, `votesControl` в `net-server.js`, К29 в `load-run.js` и `load-node.js`, канал среза в проверке Т12, `run.js --m4`.
- Модульные тесты: `test/m4-votes.test.js` (16 тестов). Правки прежних: `net-source.test.js` (ожидаемый список запросов), `m3-download.test.js` (404 у поддельного сервера).
- `check:builds` ищет в сборке ученика `votes.js`, `createVotes`, `createHmac`, `ratings.saveSnapshot`, в обеих сборках — строки стенда М4.
- Документы: `windows-m4.md`, уточнения в `etap-m4.md`, пометки «М4» в ADR-0002 (3.4, 3.7), README обоих уровней, промпт М5 в `prompty-etapov.md`. Снимки программы тьютора М1–М3 пересняты: панель называется «Оценки».

## Отступления от постановки

Подробно — в разделе «Уточнения при выполнении» постановки. Коротко:

- ещё два кода ответа: 411 без `Content-Length` и 415 не JSON;
- `vote.send` отвечает `{ ok, net, game }`, а «в очереди ли голос», витрина узнаёт из `catalog.list` (`votePending`);
- 409 на голос из очереди ученик считает доставкой: голос не посчитан, но ребёнку это не объясняем;
- Р1 и Р3 проверены модульными тестами и снимками, а не на живом окне через сеть;
- контроль К29 на стенде нагрузки — число ответов 503 (слоты были полны), отдельный «голос через слот» есть только в модульном тесте.

## Риски

1. **Ничего не проверено на Windows и в школьной сети.** Таблицы `windows-v0.md` … `windows-m4.md` пустые.
2. **Перезапуск программы тьютора начинает день заново.** Так решено в ADR-0003, но ребёнок, который знает про это, может попросить тьютора перезапустить программу. Выключение раздачи день заново не начинает.
3. **По изменению рейтинга видно, как проголосовал сосед,** если голосовали по одному (У10). Решение Влада: принято.
4. **Ребёнок со своей программой и сменой адреса** голосует по разу с каждого адреса подсети. Это ограничение ADR-0003, потолка на окно больше нет. Счётчик можно поправить только руками в `ratings.json`.
5. **Голос теряется при закрытии программы** в первые 5 с после нажатия или пока нет связи. Так в ADR-0002, на занятии это редкость.
6. **Дата дня у ученика.** Если программа ученика открыта через полночь без связи с сервером, день остаётся вчерашним (по последнему ответу тьютора) до первой связи. Сервер всё равно считает день по своим часам, лишний голос он не примет.
7. **Голоса и рейтинг идут без шифрования** (У6, У7): перехвативший Wi-Fi видит голос и может подделать рейтинг на экране. Рейтинг не имеет защитной роли.
8. **Node 18 у меня, Node 22 в Actions.** На Node 22 тесты М4 не гонялись.
