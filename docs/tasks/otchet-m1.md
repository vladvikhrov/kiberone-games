## Что сделано

- `app/shared/catalog.js`: схема и проверка каталога (`verifyCatalog`), `nextSeq`, файл школы (`makeSchoolFile`, `parseSchoolFile`). Подписи здесь нет.
- `app/shared/groups.js`: группы по `grades`, перенесены из витрины, их использует и тьютор.
- `app/shared/package-format.js`: у ошибок есть вид (`damaged`, `tampered`, `invalid`) и поле `detail` для журнала, текст без хвостов библиотек.
- `app/desktop/tutor/`: `school-key.js` (ключ), `catalog-sign.js` (подпись), `library.js` (публикация, блобы), `api.js` (14 каналов IPC), `window.js` (схема `kibtutor://`, CSP, закрытая сессия), `preload.js`, `index.js`, `main.js`, `ui/` (экраны по макету).
- `app/builder-tutor.json`: сборка «KIBERone Сервер» (`pro.kiberone.server`, `kiberone-server`), в `dist/tutor/`. Сборка ученика исключает `desktop/tutor/**`.
- `kibpack` поднимает `minAppVersion` до 1.1.0 у игр с обложками или режимами и пишет предупреждение. Обе программы версии 1.1.0, у Киберпочты, Сейфа и «Трёх режимов» `minAppVersion` 1.1.0.
- Тест-«взломщик»: `redteam/tutor-harness.js` (режимы `tutor`, `tutor-ipc`, `tutor-control`, `tutor-shots`), проверки К24, Т12, М1 в `run.js`. Снимки: `npm run shots:tutor`.
- `scripts/check-builds.js` (Т14).
- Документы: README обоих уровней, `windows-m1.md`, промпт М2 в `prompty-etapov.md`.

## Отступления от постановки

- Черновиков нет по решению Влада. Выбранный файл ждёт решения во временном `blobs/.incoming-…` и удаляется при отмене, закрытии ключа или перезапуске.
- Отдельного `library.json` нет: список игр тьютора — это последний подписанный `catalog.json`. Так список и то, что увидят ученики, не могут разойтись.
- В каталоге есть `minAppVersion`, `prefetch` (пока всегда `true`) и `icon`. Обоснование — в разделе «Дополнения при подготовке» постановки.
- Стенд витрины передавал программе версию 1.0.0, после перехода на 1.1.0 проверки В0 падали. Стенд теперь берёт версию из `package.json`. Снимки В0 в `docs/img/` не переснимались.

## Риски

1. **Ключ в памяти затирается не весь.** Буфер с ключом модуль затирает нулями, но при каждой подписи Node создаёт объект ключа внутри OpenSSL, и эту копию затереть из JavaScript нельзя. Она живёт до сборки мусора. Пароль и код в окне и в основном процессе — строки JavaScript, их тоже нельзя затереть. Защита от того, кто снимет дамп памяти работающей программы, этим не обеспечивается.
2. **Удаление `login.json` сбрасывает задержку.** Задержка защищает от перебора через окно программы. Тот, кто может удалить файл, может и скопировать `school-key.enc` и перебирать пароль у себя: тогда защищают только scrypt (N = 2^17) и длина пароля от 10 знаков.
3. **Автозакрытие считает только мышь и клавиатуру в окне.** Если тьютор 10 минут читает таблицу, не нажимая ничего, ключ закроется. Если тьютор отошёл, не заблокировав Windows, ребёнок может публиковать игры до 10 минут (остаточный риск из ADR-0002, 3.2).
4. **Два тьютора с одной школой.** После восстановления копии на втором ноутбуке у каждого свой каталог. На М2 ученик примет каталог с большим `seq`, и игры другого тьютора пропадут. Решение нужно до М2, вопрос включён в промпт.
5. **Испорченный `catalog.json`.** Список игр в программе будет пустым, файлы игр остаются в `blobs/` и не удаляются до перезапуска. Игры нужно опубликовать снова. Восстановить список из блобов программа пока не умеет.
6. **Проверено только на Linux.** Задержки, папка `%LOCALAPPDATA%`, системные окна выбора файлов и вид шрифтов на Windows не проверены.
7. **Node 18 у меня, Node 22 по README.** Тесты и сборки шли на Node 18.19. Новых возможностей Node в коде нет, но на 22 они не запускались.
