## Итог

Тьютор включает раздачу, и ноутбук ученика с меткой школы находит сервер широковещанием. Ученик проверяет подпись каталога и хеш каждого файла, качает игры в кеш и запускает их в той же песочнице. Пока идёт игра, сеть молчит. Подделанный каталог, подменённый файл, адрес «интернета» и перенаправление не проходят. Для каждой атаки есть прогон без защиты, и там она проходит. Все критерии, кроме С10 (ждёт Влада) и С12 (Windows), выполнены на Linux.

- `npm test`: 167 из 167, лог [`logs/m2-npm-test.txt`](logs/m2-npm-test.txt).

После этого прогона менялись только вид плашки раздачи и одна подпись на экране «Попроси тьютора». Повторно прошли `npm test` и `node redteam/run.js --m2` (15 из 15).

## Что сделано

- `app/shared/netif.js`: какая сеть школьная (подсеть интерфейса, без VPN и виртуальных адаптеров), строгий IPv4, широковещательные адреса. Общий для обеих программ и теста.
- `app/shared/discovery.js`: пакеты обнаружения `KIBD1` и `KIBR1` по 37 байт.
- `app/desktop/tutor/server.js`: раздача только для чтения. В `tutor/index.js`, `api.js`, `ui/` — плашка «РАЗДАЧА УЧЕНИКАМ», каналы `server.start` и `server.stop`, `powerSaveBlocker`.
- `app/desktop/school-net.js`: вся сеть ученика. `app/desktop/vitrina/net-source.js`: каталог, `seq`, очередь, кеш, проверки. `desktop/main.js`: метка школы, режим настроенного ноутбука, отказ посторонним файлам.
- Витрина: состояния карточек, точка связи, окно «Связь с тьютором», экран «Попроси тьютора», канал `server.setAddress`, событие `catalog.changed`.
- `shared/package-format.js`: `readPackage` принимает Buffer: хеш и разбор идут по одним и тем же байтам.
- Тест-«взломщик»: `redteam/net-run.js` (пространства, фазы, разбор захвата), `net-server.js` (настоящий и поддельный сервер, приёмники), `net-harness.js` (ученик, режимы с защитой и без), `school-fixture.js`, режим `tutor-serve`. Ключ `--m2` гоняет только М2, `M2_SHOTS=папка` снимает экраны.
- `scripts/make-win-zips.js` и `docs/tasks/windows-exe.md`: проверка на Windows без Node.
- Документы: README обоих уровней, `windows-m2.md`, уточнения в `etap-m2.md`, промпт М3 в `prompty-etapov.md`.

## Отступления от постановки

Подробно — в разделе «Уточнения при выполнении» постановки. Коротко:

- окно «О программе» стало окном «Связь с тьютором» и открывается нажатием на точку связи, а не из меню K1;
- метка школы на Windows читается по фиксированному пути `C:\ProgramData\…`, без переменной окружения;
- ответ на обнаружение уходит с адреса раздачи (так нашёл тест на смене адреса);
- захват не считает IGMP, как и прежний К4;
- карточка без подписи «готово», без метки «НОВОЕ», порядок — «на этом занятии», потом по названию;
- панель тьютора про оценки теперь говорит, что оценки по сети — следующий этап.

## Риски

1. **Ничего не проверено на Windows.** Ни В0, ни М1, ни М2. Самое неизвестное — брандмауэр. У тьютора программа без установщика, правило появится только из окна Windows и только для выбранного типа сети. У ученика привязка UDP-сокета может вызвать окно брандмауэра, которое ребёнок не сможет подтвердить. На это есть шаг 2а в `windows-m2.md`. Ответ сервера на широковещательный запрос Windows пропускает как ответ примерно 3 с, а витрина ждёт 2 с, но это не замерено.
2. **Изоляция клиентов в Wi-Fi.** Если ноутбуки не видят друг друга, не помогут ни обнаружение, ни ручной адрес (ADR-0002, раздел 3.5). Школьная сеть ещё не проверялась.
3. **Память на большой игре.** Игра из кеша читается в память целиком, и для 200 МБ это заметно на слабом ноутбуке. Потоковая проверка — задача М3.
4. **Без докачки и очереди.** Обрыв загрузки начинает файл заново. Нажатие «Играть» на нескачанной игре ничего не ускоряет: кнопка неактивна до конца загрузки. Это М3.
5. **Запись ученика с правами администратора** может подменить метку и кеш на своём ноутбуке (У8). Тест проверяет только то, что программа не берёт метку из переменной `ProgramData`. Права папки ставятся вручную командой из `windows-m2.md`.
6. **Windows не на диске C.** Тогда метка не найдётся, и ноутбук будет работать как ненастроенный, то есть без сети.
7. **Захват видит пакеты с адреса ученика,** а локальные пакеты игры на loopback ученика считает приёмник. Пакеты IGMP не считаются: это служебные пакеты ядра о подписке Chromium на mDNS, а не данные. Если в Electron появится новый вид фоновой сети, захват его покажет, кроме IGMP.
8. **Node 18 у меня, Node 22 в Actions.** Тесты шли на Node 18.19.
