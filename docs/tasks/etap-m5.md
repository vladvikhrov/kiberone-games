# Этап М5: установщики и пилот

Постановка к ADR-0002 (разделы 1.4, 3.3, 3.5, 3.7, 7 — этап М5, 10 — структура документации) и ADR-0003 (4.4, 8). Этап закрыт, только когда каждый критерий подтверждён запуском или наблюдением. Статус: **согласовано Владом 06.11.2026, выполнено на Linux, ждёт проверки на Windows (в отдельном чате Claude Code на Windows), установки Кириллом и пилота**. Решения — в конце, отчёт: [`otchet-m5.md`](otchet-m5.md).

## Цель

Тьютор без разработчика и без Node ставит систему по одной инструкции. Сначала программу «KIBERone Сервер» на свой ноутбук: брандмауэр настраивается сам. Потом «Игры KIBERone» на ноутбуки учеников: метка школы с флешки ложится в `C:\ProgramData` сама, и ученик не может её изменить. Затем проходит одно занятие с группой, и сбой не срывает урок.

Исходные условия (после М4, 04.11.2026):
- обе программы версии 1.1.0 собираются только папкой (`build:win-dir`, `build:tutor-win-dir`) и пакуются в zip. NSIS-установщики (`build:win`, `build:tutor-win`) после М1 не собирались. Есть только старый `dist/setup/KIBERone-Games-Setup-1.0.0.exe` без проверки (`ОТЧЁТ-WINDOWS.md`, раздел 7, пустой);
- значков `.ico` нет, папки `app/build/` нет. На этой машине нет Wine, поэтому значок и свойства файла в `.exe` встраивает только сборка на Windows (GitHub Actions);
- метку школы ставят руками командами из `windows-m2.md`, раздел 2. Правило брандмауэра никто не создаёт: Windows спрашивает при первом включении раздачи;
- `.github/workflows/build-windows.yml` собирает только установщик ученика, тесты гоняет на Node 22, программу тьютора не собирает, `check:builds` не запускает;
- сетевые проверки теста-«взломщика» (К15–К21, К25–К29, нагрузка) идут только на Linux через `unshare`. На Windows работает `run.js --portable`;
- таблицы результата `windows-v0.md` … `windows-m4.md` пустые: на Windows и на занятии ничего не проверено. Тип записи ученика на школьных ноутбуках не проверен (`ОТЧЁТ-WINDOWS.md`, находка 1), SmartScreen на скачанном файле — тоже (раздел 2);
- `games/pult.py` по ADR-0002, раздел 10, удаляется на М5.

## Что входит

**Значки и заставка** (ADR-0003, 4.4; `stil-k1.md`):
- `app/build/icon.ico` ученика: оранжевый квадрат `#FF5B14`, контур `#111`, жёсткая тень, «K1» JetBrains Mono 800, «1» ниже, как индекс. `app/build/tutor/icon.ico` тьютора: тот же знак на чёрном квадрате, с белым контуром и белой тенью, снизу оранжевая полоса (её видно с 32 px, на 16 px только знак). Размеры 16, 20, 24, 32, 40, 48, 64, 256. Рисует скрипт `scripts/make-icons.py` (Pillow, шрифт из `desktop/vitrina/ui/fonts/`), PNG-копии лежат рядом для README;
- значок файла `.kibgames` — значок ученика;
- заставка (решение 4): при каждом запуске обеих программ на 3 с плашка со знаком, тремя шагами «что делать в этой программе» и выдуманной полосой загрузки. Убирается сама, щелчком и любой клавишей (эта клавиша дальше не идёт). Сделана внутри той же страницы, без нового окна, поэтому К23 и К24 её покрывают.

**Установщик ученика** `KIBERone-Games-Setup-1.2.0.exe` (`package.json`, NSIS, `perMachine: true`, свой скрипт `build/installer.nsh`):
- ставит программу в `C:\Program Files\Игры KIBERone`, ярлык в меню «Пуск» и на рабочем столе для всех пользователей, связывает `.kibgames` с программой;
- **метка школы.** Если рядом с установщиком лежит `school.kibschool`, установщик:
  1. проверяет, что файл меньше 4 КБ и начинается с `{`. Подпись и поля проверяет сама программа при запуске (`parseSchoolFile`);
  2. создаёт `C:\ProgramData\KIBERone Games\` (путь буквами, как в `desktop/main.js`, не из переменной);
  3. если папка уже была, делает её владельцем группу «Администраторы»: иначе ученик, заранее создавший эту папку, остался бы её владельцем и смог бы поменять права;
  4. копирует файл в `school.json`, снимает наследование и даёт права: «Администраторы» и SYSTEM — полный доступ, «Пользователи» — только чтение и выполнение (`icacls` по SID, как в `windows-m2.md`).
  Если файла нет — ставит программу без метки и говорит об этом (решение 2). Молчаливая установка `Setup.exe /S` делает то же самое без окон: администратор может ставить её на 15 ноутбуков с флешки;
- в последнем окне установщика: «Метка школы «Название» поставлена» или «Метки школы нет: игры открываются только из файлов, сети нет»;
- **обновление** поверх старой версии метку и кеш не трогает (NSIS-макросы electron-builder вызывают удаление старой версии, проверяется `${isUpdated}`);
- **удаление** снимает программу, ярлыки, ассоциацию и метку (решение 3). Кеш `%LOCALAPPDATA%\KIBERone Games` других записей Windows не удаляется: установщик к ним доступа не имеет, об этом сказано в инструкции.

**Установщик тьютора** `KIBERone-Server-Setup-1.2.0.exe` (`builder-tutor.json`, NSIS, `perMachine: true`, `build/tutor/installer.nsh`):
- ставит программу в `C:\Program Files\KIBERone Сервер`, ярлыки, значок тьютора;
- **правило брандмауэра** (ADR-0002, 3.7): два входящих правила с именем `KIBERone Server 47800` — TCP 47800 и UDP 47800, только для `$INSTDIR\kiberone-server.exe`, `remoteip=localsubnet`, `profile=any`. Создаются через `netsh advfirewall firewall`, перед созданием прежние правила с этим именем удаляются, поэтому повторная установка не плодит копии. Имя латиницей: `netsh` из NSIS с кириллицей не проверен;
- **удаление** снимает оба правила, а при обновлении их оставляет. Данные школы (`%LOCALAPPDATA%\KIBERone Server`: ключ, каталог, `blobs`, `trusted-keys.json`, `ratings.json`) не удаляются (`deleteAppDataOnUninstall: false`);
- в последнем окне — напоминание: «Код восстановления — на бумаге, резервная копия — кнопкой «Школа» → «Резервная копия»».

**Обе программы:**
- версия 1.2.0. `minAppVersion` старых игр (1.1.0) по-прежнему проходит;
- Electron fuses, отказ от ключей запуска у установленной программы, CSP витрины, песочница игр не меняются;
- установщик не подписан (подпись кода Windows не входит). Что покажет SmartScreen, записываем в `windows-m5.md` и объясняем в инструкции.

**Сборка в GitHub Actions** (`.github/workflows/build-windows.yml`, запуск вручную):
- задание `windows` (windows-latest, Node 22): `npm ci`, `npm test`, `node redteam/run.js --portable`, `npm run build:win`, `npm run build:tutor-win`, затем `node scripts/check-builds.js --no-build` по папкам `win-unpacked`, из которых собраны установщики, и проверка, что в `.exe` встроен значок. Выход: оба установщика и `SHA256SUMS.txt` одним артефактом;
- задание `linux` (ubuntu-latest, Node 22): полный `node redteam/run.js` и `node redteam/load-run.js --quick` под `xvfb-run`. Для `unshare -Urn` на Ubuntu 24.04 нужно разрешить непривилегированные пространства имён (`sysctl kernel.apparmor_restrict_unprivileged_userns=0`). Так все К1–К29 гоняются на Node 22 в чистом окружении (риск 8 из `otchet-m4.md`). Если на раннере не получится, задание помечается необязательным, и это записывается в отчёт;
- стабильность К3 (`ОТЧЁТ-WINDOWS.md`, находка 2): вместо `sleep(900)` после перехода стенд ждёт события загрузки, а потом короткую паузу. Иначе случайный провал контрольного прогона роняет весь workflow.

**Документация** по ADR-0002, раздел 10. Правило: ни одна инструкция не повторяется в двух местах.
- `README.md` в корне — на один экран: что это, схема «Как игра попадает к ученику» (Mermaid `flowchart`), значки, установка в трёх шагах со ссылкой на `ustanovka.md`, таблица ссылок;
- `docs/ustanovka.md` — **для тьютора, главный документ М5.** Что скачать и как проверить хеш; что делать с окном SmartScreen; установка программы тьютора, создание школы, пароль, код восстановления на бумаге, резервная копия; `school.kibschool` на флешку рядом с установщиком ученика; установка на ноутбуки учеников, в том числе `/S`; первое занятие: включить раздачу, выбрать сеть, «На этом занятии»; таблица «что сломалось — что делать» (из ADR-0002, 3.5, и «Когда сервер пропал»); обновление, удаление, где лежат данные; замена ноутбука тьютора. Без команд PowerShell там, где можно обойтись мышью;
- `docs/kak-ustroeno.md` — для разработчика: компоненты, потоки, API (по ADR-0002, 2 и 3.4 с пометками М4, без копирования ADR целиком), схемы «Как игра попадает к ученику» и «Запуск и загрузка по шагам» (`sequenceDiagram`);
- `docs/kak-sdelat-igru.md` — для автора игры: `kibgame.json`, `cover`, `modes`, `kibpack` (ключ, упаковка, проверка), что игра не может (сеть, файлы, устройства), предел размера, проверка игры до публикации;
- `docs/bezopasnost.md` — что обещаем и что нет, какие данные где лежат (таблица из ADR-0002, 3.7), модель угроз кратко, что защищают оценки и чего не защищают (ADR-0003, 10, и риски `otchet-m4.md`), тест-«взломщик» и контрольные прогоны. Схема «Кому что доверяем» (`flowchart`);
- `docs/plan.md` — этапы В0, М1–М5 и их статус, ссылки на постановки и отчёты, что дальше (ADR-0002, раздел 9);
- `app/README.md` — только для разработчика: команды, сборка, тесты. Части, которые переезжают в `ustanovka.md` и `kak-ustroeno.md`, заменяются ссылками;
- ADR-0001 и ADR-0002 не переписываются, в ADR-0002 добавляются пометки «М5:» там, где сделано иначе.

**Удаление пульта** (решение 5): `games/pult.py`, `games/pult-config.json`, раздел о пульте в `games/README.md`. `games/index.html` остаётся как меню для запуска без приложения.

**Задания для Влада и Кирилла:**
- `docs/tasks/windows-m5.md` — установка на чистый Windows 11 и на школьный ноутбук под записью ученика, без Node: SmartScreen и Защитник на файле, скачанном браузером (с отметкой «из интернета»), `Get-NetFirewallRule` до и после установки и удаления, попытки записи метки из записи ученика, обновление поверх старой версии, удаление. Таблица результата;
- `docs/tasks/kirill-ustanovka.md` — лист наблюдения: Кирилл ставит систему по `ustanovka.md`, Влад молча записывает каждое место, где Кирилл застрял, и сколько времени ушло на каждый шаг. По итогам правится `ustanovka.md`;
- `docs/tasks/pilot-m5.md` — чек-лист пилота на одной группе: подготовка накануне, что делать при каждом сбое (вместе с «план Б»: урок по модулю без игр), что наблюдать, таблица итогов. Данных о детях не собираем: ни имён, ни снимков экранов с детьми.

## Что не входит

Автообновление. Подпись кода Windows. Несколько школ. Рейтинг учеников, ники. Установка по сети на все ноутбуки сразу (групповые политики, Intune). Изменения витрины и программы тьютора сверх значка и заставки. Новые игры. Перевод на другие языки. Снимки окон установщика в документации: на Linux их не снять, они добавятся по снимкам Влада.

## Порядок работы

1. Значки: `scripts/make-icons.py`, `build/icon.ico`, `build/tutor/icon.ico`, PNG для README, модульный тест на размеры. Покажу Владу картинки до сборки.
2. Заставка — по ответу на вопрос 4.

## Уточнения при выполнении

- **Установщики собирает чат на Windows**, а не только GitHub Actions: на Windows electron-builder встраивает значок и свойства в exe без Wine. Workflow остаётся (два задания: Windows и Linux), запуск по желанию. Проверка собранного — `app/scripts/check-installers.js`: fuses в exe, значок (байты PNG 256 px из `.ico` в ресурсах exe), установщики и `SHA256SUMS.txt` в `dist/installers/`. Контроль проверки fuses: на чистом Electron она видит включённый `RunAsNode`.
- **И10 без второго выпуска в репозитории:** сборка 1.2.1 — `-c.extraMetadata.version=1.2.1` на Windows или поле `version` workflow; `package.json` не меняется.
- **Заставка мешала стенду** (закрывает окно 3 с и съедает первую клавишу), поэтому стенды витрины, тьютора и сети убирают её сразу после загрузки страницы (`redteam/*-harness.js`, `web-contents-created`). Снимки самой заставки — `redteam/splash-shots.js`, `docs/img/m5-zastavka-*.png`.
- **К3:** вместо ровно 900 мс после перехода стенд ждёт до 4 с смены адреса или нового окна и ещё 700 мс. Защищённый прогон стал дольше примерно на 40 с, зато строже.
- **Папка-ссылка.** Кроме владельца папки установщик снимает junction на месте `C:\ProgramData\KIBERone Games` и ссылку на месте `school.json`: иначе ученик мог бы направить метку в свою папку. В `windows-m5.md` это отдельная проверка.
- **Значки рисует скрипт** `app/scripts/make-icons.py` (Pillow и fontTools, шрифт JetBrains Mono из витрины). У тьютора оранжевая полоса сверху (как в программе), видна с 32 px.
- **Документы:** клиентский код в `app/desktop/vitrina/` и `school-net.js`, а не в `desktop/client/`, как в разделе 10 ADR-0002. Ссылки, повторы абзацев, длина README и отсутствие пульта проверяются `app/test/m5-docs.test.js`.
