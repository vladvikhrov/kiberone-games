# Этап В0: витрина в приложении ученика, без сети

Постановка задачи к ADR-0003. Этап закрыт, только когда каждый критерий подтверждён запуском.

## Цель

Сделать настоящее окно витрины в Electron-приложении в утверждённом стиле (`docs/stil-k1.md`), чтобы его можно было показать детям и Кириллу до того, как готовы сервер и ключ школы. Игры берутся из локальной папки, запускаются в той же песочнице, что и сейчас.

## Что входит

- Окно витрины: шапка K1, фильтр по группам, сетка карточек, обложки и заглушка, звёзды и среднее, состояния карточки.
- Окно игры поверх витрины: анимация из карточки, вкладки режимов, «Играть», крестик, Esc, щелчок мимо, возврат фокуса.
- Окно оценки после закрытия игры: 5 звёзд, 5 с на отмену, «одна оценка режима в день с ноутбука» на стороне ученика (`state.json`).
- Источник каталога для разработки: папка с `.kibgames`, каждая проверяется существующим `readPackage`. Оценки на этом этапе пишутся в локальный `ratings.json` той же формы, что будет на сервере (ADR-0003, раздел 10), чтобы проверить подсчёт и показ.
- Поля манифеста `cover` и `modes` (с `title`, `about`, `entry`, `cover`) в `shared/package-format.js` и `kibpack`, со всеми проверками из ADR-0003 5.1 и ADR-0002 3.6. Обложки у Киберпочты и Сейфа. Режимы в них не придумываю: несколько режимов проверяются на тестовой игре.
- Безопасность окна витрины: своя схема `kibapp://`, своя сессия в памяти, без Node и сети, CSP, IPC только `catalog.list`, `game.launch(id, mode)`, `vote.send`, событие `game.closed`.
- Шрифты Golos Text и JetBrains Mono внутри приложения.

## Что не входит

Сеть, сервер, обнаружение, ключ школы, подпись каталога, панель тьютора (этапы М1–М2), докачка (М3), установщики (М5). Защита от повторов на сервере появится вместе с сервером.

## Критерии приёмки

| № | Критерий | Как проверяется |
| --- | --- | --- |
| В1 | Витрина выглядит как макет на 1366 × 768 и 1920 × 1080 | Снимки экрана в `docs/img/`, сверяет Влад |
| В2 | В CSS нет градиентов (кроме штриховки), `blur`, `backdrop-filter`, `border-radius` больше 0 | Поиск строк в тесте |
| В3 | «Играть» открывает выбранный режим в песочнице, после закрытия появляется окно оценки этого режима | Тест через Electron и вручную на Киберпочте и Сейфе |
| В4 | Оценка уходит через 5 с, «Отменить» в это время её снимает | Модульный тест с поддельными часами и вручную |
| В5 | Тот же режим нельзя оценить второй раз в тот же день, назавтра можно. Другой режим можно | Модульный тест со сменой даты |
| В6 | Среднее и число оценок считаются из `ratings.json` верно, при `n < 5` показывается «мало оценок» | Модульный тест |
| В7 | Плохие `cover` и `modes` отвергаются: JPEG, подмена расширения, больше 512 КБ, путь вне `game/`, 13 режимов, плохой `id`, `entry` вне `game/` | Модульные тесты на каждый случай, контроль: верный манифест принимается |
| В8 (К23) | Окно витрины не выходит в сеть и не выполняет разметку из каталога: игра с названием `<img src=x onerror=…>` показывает его как текст | Тест-«взломщик». Контроль: версия без CSP и с `innerHTML` выполняет. Иначе тест провален |
| В9 | IPC витрины принимает только 4 канала, неизвестный канал и чужой `id` игры отклоняются | Тест |
| В10 | Все К1–К14 проходят как раньше | `npm test` и `node redteam/run.js` |
| В11 | Работает без интернета, шрифты не грузятся извне | Захват или журнал запросов: 0 внешних обращений |
| В12 | При `prefers-reduced-motion` анимаций нет, всё доступно с клавиатуры, кнопки не меньше 44 px | Вручную и в DevTools |
| В13 | Дети понимают без объяснений, как запустить игру и оценить | Показ 3–4 ученикам, тьютор записывает, где застряли. Данные о детях не собираем |
| В14 | Проверено на Windows | Прогон В3–В6, В10, В11 на ПК Влада, отчёт |

## Порядок работы

1. Формат: `cover` и `modes` в `shared/` и `kibpack`, тесты В7.
2. Логика оценок без интерфейса: счётчик, среднее, правило дня, тесты В4–В6.
3. Окно витрины и его защита, тесты В8, В9.
4. Интерфейс по макету, снимки В1.
5. Обложки для Киберпочты и Сейфа, тестовая игра с тремя режимами.
6. Прогоны В10–В12 на Linux, затем В14 на Windows, затем В13 с детьми.
