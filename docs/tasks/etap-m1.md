# Этап М1: ключ школы, публикация и подписанный каталог, программа тьютора

Постановка к ADR-0002 (раздел 7, этап М1) с дополнениями ADR-0003 (разделы 5.2, 8, 10). Этап закрыт, только когда каждый критерий подтверждён запуском. Статус: **согласовано Владом 03.11.2026, в работе**.

## Цель

Доказать цепочку доверия на одной машине без сети: тьютор создаёт школу, публикует проверенные игры, программа подписывает каталог ключом школы, а модуль проверки в `app/shared/` принимает только верный каталог. Заодно появляется программа тьютора «KIBERone Сервер» в утверждённом стиле (`docs/stil-k1.md`, экран 4 макета).

## Что входит

**Сборка тьютора.** Свой вход `app/desktop/tutor/main.js`, свой конфиг electron-builder (`appId pro.kiberone.server`, окно «KIBERone Сервер»). Общий код берётся из `app/shared/` и `app/desktop/sandbox.js` (пробный запуск игры). Из сборки ученика `app/desktop/tutor/**` исключается.

**Ключ школы** (`app/desktop/tutor/school-key.js`):
- создание школы: название, пароль от 10 знаков дважды, ключ Ed25519;
- на диске только `school-key.enc`: две копии закрытого ключа, AES-256-GCM, ключ шифрования из `scrypt` (N = 2^17, r = 8, p = 1, своя соль у каждой копии): одна копия под паролем, вторая под кодом восстановления;
- код восстановления: 26 знаков base32 (128 бит), показывается один раз при создании, тьютор подтверждает, что записал;
- вход по паролю; после каждой ошибки задержка растёт (1, 2, 4 … до 60 с), счётчик ошибок переживает перезапуск программы;
- восстановление: код → новый пароль;
- автозакрытие панели через 10 минут без действий: закрытый ключ затирается нулями и выбрасывается из памяти;
- резервная копия: папка с `school-key.enc` и `school.kibschool`, восстановление школы из неё на другом ноутбуке (второй тьютор).

**Каталог** (`app/shared/catalog.js`, общий для обеих программ):
- содержимое по ADR-0002 3.4 плюс ADR-0003 5.2: `format`, `school`, `seq`, `games[]` с `id`, `version`, `title`, `description`, `grades`, `minutes`, `topic`, `author` (имя из списка доверия школы), `authorKey`, `sha256`, `bytes`, `icon`, `cover {sha256, bytes}`, `publishedAt`, `lesson`, `modes[] {id, title, about, cover}`;
- подпись Ed25519 точных байтов `kibcatalog-v1\n` + содержимое; файл `catalog.json` = `{ "payload": base64, "sig": base64 }`, до 2 МБ;
- `seq = max(прежний + 1, unix-время)`;
- проверка для ученика (`verifyCatalog`): подпись ключом школы, префикс, строгая схема (лишние поля и неверные типы отвергаются), `seq` больше сохранённого, размер. Подключение проверки к витрине — этап М2.

**Файл школы** `school.kibschool`: `{ format, name, publicKey, fingerprint }`, только публичный ключ. Проверка и разбор в `app/shared/`.

**Публикация** (`app/desktop/tutor/library.js`):
- «Добавить .kibgames»: файл выбирает системное окно в основном процессе, окно тьютора путей не видит; `readPackage`; программа показывает игру, автора, отпечаток ключа;
- неизвестный автор: предупреждение, публикация только после явного подтверждения; по желанию тьютор вносит автора в список доверия школы под своим именем;
- `id` уже есть с другим ключом автора: публикация запрещена до отдельного подтверждения замены;
- новая версия того же автора заменяет старую, более старая версия отвергается без подтверждения;
- файл копируется в `blobs/<sha256>`, обложки игры и режимов — в `blobs/<sha256>` из уже проверенных байтов, без перекодирования;
- черновиков нет (решение Влада): выбранный файл до публикации лежит во временной папке `blobs/` и показывается в окне проверки, где есть «Пробный запуск», «Опубликовать» и «Отмена». «Опубликовать» сразу добавляет игру в каталог и подписывает его, «Снять» убирает игру из каталога совсем. `publishedAt` ставится при первой публикации и сохраняется при новой версии;
- отметка «на этом занятии» (`lesson`) тоже идёт в подписанный каталог;
- «Пробный запуск» открывает игру в существующей песочнице: и до публикации, и для игры из каталога;
- блоб, на который не ссылается ни одна игра, удаляется.

**Окно тьютора** по экрану 4 макета: полоса «ТЬЮТОР», чёрная шапка с K1 и «Игры школы», состояние ключа, кнопка «Опубликовать .kibgames» (добавить файл); таблица ИГРА / ВОЗРАСТ / АВТОР / РЕЙТИНГ / СТАТУС (статус «в каталоге» или «на занятии»), под таблицей кнопки для выбранной игры: «Пробный запуск», «На этом занятии», «Снять»; панель «Оценки за занятие» по выбранной игре: режимы, среднее, число, полосы распределения 5 → 1 — из локального `ratings.json` через `shared/ratings.js`. Отдельные экраны: создание школы или восстановление из резервной копии, код восстановления. Когда ключ закрыт, таблица и оценки видны, а действия с каталогом просят войти (окно входа с «Забыли пароль?»). Окно «Школа»: название, отпечаток, «Сохранить school.kibschool», «Резервная копия», «Закрыть ключ». Шрифты и токены — те же файлы, что у витрины.

**Безопасность окна тьютора** — та же модель, что у витрины: своя схема `kibtutor://`, сессия в памяти, без Node и сети, CSP с Trusted Types, тексты из `.kibgames` только через `textContent`, IPC только из заранее заданного списка (см. критерий Т12), основной процесс проверяет каждый аргумент. Пароль и код идут из окна в основной процесс один раз и в окне не хранятся.

**Хранение** по ADR-0002 3.7: `%LOCALAPPDATA%\KIBERone Server\` (`school-key.enc`, `login.json` со счётчиком ошибок входа, `school.kibschool`, `catalog.json`, `blobs\`, `trusted-keys.json`, `ratings.json`). Отдельного `library.json` нет: список игр тьютора — это последний подписанный `catalog.json`, при запуске программа проверяет его ключом школы. На Linux — `~/.local/share/KIBERone Server/`. Запись атомарная.

**Ошибки по-русски** (находка 4 `ОТЧЁТ-WINDOWS.md`, ADR-0003 раздел 6): у `readPackage` нет хвостов из ZIP-библиотеки в тексте для человека (они уходят только в журнал), «файл повреждён» и «файл изменён после подписи» различаются. В обеих программах вместо `dialog.showErrorBox` (заголовок «Error» на Windows) — окно с русским заголовком.

## Что не входит

Сервер в сети, обнаружение, раздача и `powerSaveBlocker` (М2), витрина ученика по подписанному каталогу и метка школы в `%ProgramData%` (М2), сброс оценок и окна оценок, «Сохранить срез» (М4), установщики и значки `.ico` (М5). Изменения окна витрины ученика — только если этого потребуют результаты Влада по В1, В13, В14.

## Критерии приёмки

| № | Критерий | Как проверяется |
| --- | --- | --- |
| Т1 | Ключ на диске только зашифрован | Модульный тест: после создания школы, входа, публикации и закрытия в папке данных нет 32 байтов закрытого ключа ни в одной кодировке (сырые, base64, hex, PEM). Контроль: тот же поиск находит байты в нешифрованной копии |
| Т2 | Неверный пароль не открывает ключ, задержка растёт до 60 с и не сбрасывается перезапуском | Модульный тест с поддельными часами: 1, 2, 4 … 60 с; новый экземпляр модуля видит тот же счётчик; верный пароль после задержки открывает |
| Т3 | Пароль короче 10 знаков не принимается | Модульный тест |
| Т4 | Восстановление кодом работает, неверным и испорченным кодом нет, после восстановления старый пароль не подходит | Модульный тест |
| Т5 | Изменённый байт в `school-key.enc` (соль, шифр, метка) даёт понятную ошибку, а не ключ | Модульный тест на каждое поле |
| Т6 | Через 10 минут без действий панель закрыта, ключа в памяти нет; действие сбрасывает отсчёт | Тест с поддельными часами: буфер ключа затёрт нулями, подпись без входа отклонена |
| Т7 | Резервная копия восстанавливает ту же школу на «другом ноутбуке» (новая папка данных): тот же отпечаток, подпись проверяется старым `school.kibschool` | Модульный тест |
| Т8 | Каталог с чужой подписью, изменённым байтом, другим префиксом, без префикса, старым и равным `seq`, лишним полем, неверным типом, больше 2 МБ отвергается | Модульный тест на каждый случай. Контроль: верный каталог принимается |
| Т9 | `seq` растёт: при откате часов назад и при быстрых публикациях подряд | Модульный тест с поддельными часами |
| Т10 | Вредные, чужие и подменённые игры не публикуются без явного решения: битый и подделанный файл (К11), самозванец с тем же `id` и другим ключом (К13), неизвестный автор, старая версия | Модульные тесты: без подтверждения каталог не изменился; с подтверждением — изменился, где это допустимо (битый файл не публикуется никогда) |
| Т11 | Обложки в `blobs/` побайтно равны обложкам из `.kibgames`, их `sha256` и размеры в каталоге верны, у режимов свои; после снятия игры лишние блобы удалены | Модульный тест на «Трёх режимах» |
| Т12 | IPC окна тьютора принимает только каналы из списка; пути к файлам из окна не принимаются; без входа действия с ключом отклонены | Тест с мостом к сырому `ipcRenderer`, как В9. Контроль: верные вызовы работают |
| Т13 (К24) | Окно тьютора не выполняет разметку из `.kibgames` и не выходит в сеть | Тест-«взломщик», игра с разметкой в названии, авторе, режиме. Контроль: та же страница без CSP, без закрытой сессии и с `innerHTML` выполняет и доходит до приёмника, иначе тест провален |
| Т14 | В сборке ученика нет кода тьютора; в сборке тьютора он есть | `npx asar list` обеих сборок `--linux dir`: в ученической нет `desktop/tutor/`, `school-key`, `catalog-sign`; в тьюторской есть (контроль) |
| Т15 | Ошибки по-русски, без хвостов библиотек; «повреждён» и «изменён после подписи» различаются | Модульный тест: `bitaya` и `poddelka` из комплекта Windows, тексты без латиницы, кроме имён файлов; К11 проходит с новыми текстами |
| Т16 | Экран тьютора выглядит как экран 4 макета на 1366 × 768 и 1920 × 1080 | Снимки в `docs/img/`, сверяет Влад; поиск запрещённого в CSS, как В2 |
| Т17 | Все К1–К14, К23 и проверки В0 проходят как раньше | `npm test` и `node redteam/run.js` |
| Т18 | Проверено на Windows | Прогон Т1–Т15, Т17 и ручная проверка по `windows-m1.md` на ПК Влада |

## Порядок работы

1. Ошибки по-русски в `readPackage` и окна ошибок (Т15), чтобы дальше всё строилось на новых текстах.
2. `shared/catalog.js` и `school.kibschool`: формат, подпись, проверка, `seq`, тесты Т8, Т9.
3. `tutor/school-key.js`: создание, вход, задержка, код, автозакрытие, резервная копия, тесты Т1–Т7.
4. `tutor/library.js`: добавление, решения о доверии и замене, черновик и каталог, блобы, тесты Т10, Т11.
5. Окно тьютора и его защита, тесты Т12, Т13 (К24).
6. Интерфейс по макету, снимки Т16.
7. Две сборки и проверка `app.asar` (Т14).
8. Прогоны Т17 на Linux, затем `windows-m1.md` и Т18 у Влада.

## Решения Влада от 03.11.2026

| Вопрос | Решение |
| --- | --- |
| Версия | Пока 1.1.0 у обеих программ, общую схему версий сделаем позже. `kibpack` сам ставит `minAppVersion: "1.1.0"`, если в игре есть `cover` или `modes`, а автор указал меньше, и пишет об этом предупреждение |
| Группы в фильтре | На усмотрение Claude: остаются по тексту `grades`, как на В0. Колонка ВОЗРАСТ в таблице тьютора показывает те же группы |
| Обложки Киберпочты и Сейфа | Остаются нарисованные Claude |
| «Черновик» из макета | Убрать. Публикация сразу в каталог, «Снять» убирает игру из каталога |
| Панель «Оценки за занятие» | Подпись «всего», а не «сегодня» |
| Блоб файла игры | `blobs/<sha256>` без расширения, как обложки |
| Изменения витрины ученика | Не нужны: проверка на Windows и показ детям ещё не проводились |

## Дополнения при подготовке

- В записи игры каталога кроме полей ADR-0002 3.4 и ADR-0003 5.2 есть `minAppVersion`: без него ученик на М2 узнает, что игре нужна новая программа, только после загрузки. Поле `prefetch` из ADR-0002 3.4 включено сразу (на М1 всегда `true`), иначе строгая проверка каталога отвергла бы его на М3 у старых программ. `icon` — `{ sha256, bytes }` из `icon.png` (PNG до 64 КБ) или `null`.
- `author` в каталоге — имя из списка доверия школы. Если тьютор опубликовал игру неизвестного автора, не внеся его в список, `author` равен `null`.
- Подписание каталога лежит в `app/desktop/tutor/catalog-sign.js`, в `app/shared/catalog.js` только проверка, схема и `seq`: так в сборке ученика нет кода подписи (Т14).
- Неверный пароль и подделанный злоумышленником `school-key.enc` неразличимы (так устроен AES-GCM). Случайную порчу файла различаем: в файле есть контрольная сумма полей, при её несовпадении текст «Файл ключа повреждён», иначе «Пароль не подошёл».
- Автозакрытие считает действием нажатие мыши или клавиши в окне тьютора (событие `input-event` основного процесса), отдельного канала IPC для этого нет.
- Тексты ошибок `readPackage` получают вид ошибки: `damaged` («Файл повреждён…»), `tampered` («Файл изменён после подписи…»), `invalid` (нарушение формата). Технические подробности уходят только в журнал.

## Уточнения при выполнении

- Проверка интерфейса тьютора целиком (создание школы, код, публикация с подтверждением, закрытие ключа) вынесена в тест-«взломщик» отдельной строкой «М1». Её нет в таблице критериев, но она подкрепляет Т3, Т10 и Т16.
- Стенд витрины в тесте-«взломщике» передавал программе версию «1.0.0». После перехода на 1.1.0 «Три режима» требуют 1.1.0, и проверки В3–В5, В9, В12 падали. Стенд теперь берёт версию из `package.json`, как настоящая программа.
- Пробный запуск режима, которого нет в игре, отклоняет песочница (`openGame`), а не IPC: список режимов знает только пакет.
- Т14 проверяется скриптом `npm run check:builds`. Он собирает обе программы папкой и ищет в `app.asar` файлы `desktop/tutor/`, `school-key`, `catalog-sign` и строки `kibtutor`, `school-key.enc`, `signCatalog`, `createSchoolKey`. Сборка тьютора — контроль: в ней всё это должно найтись.
