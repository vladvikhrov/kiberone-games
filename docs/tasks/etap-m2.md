# Этап М2: каталог и запуск игры по сети

Постановка к ADR-0002 (раздел 7, этап М2) с дополнениями ADR-0003 (разделы 2.1, 5.2, 5.3, 6, 8). Этап закрыт, только когда каждый критерий подтверждён запуском. Статус: **согласовано Владом 03.11.2026, выполнено на Linux, ждёт проверки на Windows (С10, С12)**. Отчёт: [`otchet-m2.md`](otchet-m2.md).

## Цель

Ученик видит каталог школы с сервера тьютора в локальной сети и запускает полученную по сети игру. Сервер при этом считается ненадёжным: на экран и в песочницу попадает только то, что подписано ключом школы и совпало по `sha256`. Ноутбук ученика ходит в сеть только к адресам своей подсети, без DNS, и молчит, пока идёт игра.

Исходные условия (ответы Влада от 03.11.2026): в классе один ноутбук тьютора и одна программа тьютора, она и раздаёт каталог. Каталоги разных серверов не объединяются. Витрина В0 меняется только там, где этого требует каталог по сети.

## Что входит

**Сервер только для чтения в программе тьютора** (`app/desktop/tutor/server.js`, в сборку ученика не входит):
- Node `http` на порту 47800, только на адресе интерфейса, который выбрал тьютор;
- `GET /v1/catalog`: байты текущего `catalog.json`, `ETag` равен `"<seq>"`, на `If-None-Match` с тем же значением ответ 304;
- `GET /v1/blobs/sha256/<hex>`: только `[0-9a-f]{64}` и только хеши, на которые ссылается текущий подписанный каталог (файлы игр, обложки, значки). Временные файлы `.incoming-…` не отдаются. `Content-Length`, `Cache-Control: immutable`. `Range` не поддерживается (М3);
- отказ: заголовок `Origin` (403), адрес не из подсети выбранного интерфейса (соединение закрывается без ответа), метод не `GET` и не `HEAD` (405), любой другой путь, в том числе с `..` и `%2e` (404), запрос с телом (413), заголовки больше 8 КБ. Таймауты заголовков и простоя, предел одновременных соединений;
- журнала запросов нет ни на диске, ни в окне;
- UDP 47800 для обнаружения. Сокет слушает `0.0.0.0`, потому что на Linux сокет на конкретном адресе не получает широковещание. Сервер отвечает только отправителю из подсети выбранного интерфейса и только на запрос с отпечатком своей школы. Ответ не больше запроса;
- раздача выключена при каждом запуске программы. Кнопка «Включить раздачу» с выбором интерфейса: в списке название интерфейса и адрес. Включённая раздача показывает «Адрес для учеников: 192.168.1.50». Раздача работает и при закрытом ключе: каталог уже подписан. Пока раздача включена, `powerSaveBlocker` не даёт ноутбуку уснуть;
- новый каталог после публикации или снятия игры отдаётся сразу, без перезапуска раздачи;
- брандмауэр: команд и правил программа не создаёт. При первом включении раздачи Windows сама показывает окно «Разрешить доступ», тьютор отмечает тип сети. Подсказка в окне тьютора рядом с кнопкой: «Если Windows спросит про доступ к сети, отметьте сеть, к которой подключены, и нажмите «Разрешить»». Подсеть проверяет сам сервер, поэтому `localsubnet` в правиле не нужен.

**Выбор интерфейса** (`app/shared/netif.js`, общий для обеих программ):
- IPv4, не loopback, подсеть самого интерфейса (адрес и маска из системы), как в ADR-0002. Ограничений на частные адреса и ширину маски нет (решение Влада);
- адаптеры VPN и виртуальные не считаются школьной сетью: по имени (`happ`, `xray`, `v2ray`, `clash`, `tun`, `tap`, `wg`, `wireguard`, `openvpn`, `vpn`, `tailscale`, `zerotier`, `hamachi`, `vEthernet`, `VirtualBox`, `VMware`, `docker`, `WSL` и подобные) и по адресу (`/32`, `/31`). Находка 5 `ОТЧЁТ-WINDOWS.md`: адаптер `happ-xray` с адресом 172.19.0.1 не должен выбираться;
- у тьютора такие интерфейсы в списке не показываются. Если подходящего нет: «Не нашёл школьную сеть. Подключите ноутбук к Wi-Fi или кабелю»;
- `lanIp()` в `redteam/run.js --portable` берёт адрес через тот же модуль.

**Настроенный ноутбук ученика** (ADR-0002, 3.3):
- метка школы `%ProgramData%\KIBERone Games\school.json`, содержимое — файл `school.kibschool` без изменений, проверка `parseSchoolFile`. На Linux `/etc/kiberone-games/school.json`. Из исходников путь задаётся ключом `--school=файл`, у собранной программы ключей нет, как и раньше;
- без метки приложение работает как на В0: игры из папки, сети нет, ни одного пакета (К4);
- с меткой витрина берёт игры только из каталога школы. Папка `games\` и `trusted-keys.json` не читаются: доверие к автору даёт подписанный каталог (`authorKey`);
- посторонний `.kibgames` (двойной щелчок, аргумент) на настроенном ноутбуке не открывается: «На этом ноутбуке игры запускаются только из каталога школы»;
- испорченная метка: витрина показывает «Ноутбук настроен с ошибкой. Скажи тьютору», сети нет.

**Сетевой модуль ученика** (`app/desktop/school-net.js`, один файл основного процесса, ADR-0002, 4.1):
- только Node `http` и `dgram`, модуль `net` из Electron не используется;
- фильтр перед каждым подключением и каждой отправкой UDP: IPv4-литерал из подсети подходящего интерфейса (`netif.js`) или широковещательный адрес этой подсети и `255.255.255.255`. `lookup` всегда возвращает ошибку, перенаправления не выполняются, `agent: false`;
- пределы: каталог 2 МБ, обложка 512 КБ, значок 64 КБ, игра — `bytes` из каталога. Чтение обрывается, как только пришло больше. Таймаут простоя 30 с;
- тексты ошибок для журнала. Ребёнок видит только тексты из таблицы ADR-0003, раздел 6.

**Обнаружение** (ADR-0002, 3.5):
1. последний рабочий адрес из `state.json`;
2. UDP `KIBD1` + отпечаток школы + случайное число на `255.255.255.255` и на широковещательный адрес каждого подходящего интерфейса;
3. ответы с чужим отпечатком, чужим числом или с адреса не из подсети отбрасываются. Адрес сервера — адрес отправителя ответа, адреса внутри ответа не используются. Каталог проверяется у каждого ответившего, берётся наибольший `seq`;
4. через 15 с без каталога и без кеша — экран «Попроси тьютора» с полем адреса. Адрес проходит тот же фильтр и запоминается. Если кеш есть, витрина показывает его и «нет связи» в шапке; нажатие на «нет связи» открывает то же поле адреса.

**Каталог и кеш ученика** (ADR-0002, 2.2 и 3.7):
- данные в `%LOCALAPPDATA%\KIBERone Games\` (Linux: `~/.local/share/KIBERone Games/`): `catalog.json` (последний принятый), `state.json` (`seq`, последний адрес), `cache\<sha256>` (игры и обложки, имя файла равно хешу);
- каталог принимается, только если `verifyCatalog` прошёл с ключом из метки и `seq` больше сохранённого. При запуске кеш каталога проверяется подписью заново;
- опрос каждые 60 с со сдвигом до 15 с, с `If-None-Match`;
- сначала обложки игр, потом обложки режимов, потом игры, по одному файлу за раз. Игры с `minAppVersion` новее программы не качаются;
- файл пишется во временный, проверяется `sha256` и размер, игра ещё и `readPackage` с ключом автора из каталога (`id`, `version`, `authorKey` совпадают), затем переименование в `cache\<sha256>`. Неудачная загрузка повторяется при следующем опросе, после 3 неудач подряд за запуск программы игра получает состояние «не скачалась»;
- файлы игр и обложек, которых нет в новом каталоге, удаляются;
- запуск: снова `readPackage` файла из кеша и сверка `sha256` и ключа автора с каталогом, затем существующий `openGame` с режимом.

**Витрина** (изменения В0 только для каталога по сети):
- источник каталога: сеть и кеш вместо папки, если ноутбук настроен;
- состояния карточки из ADR-0003, 2.1: `✓ готово`, полоса с процентами при загрузке, `нужна связь` (обложка приглушена, кнопка «Попроси тьютора включить раздачу»), `не скачалась` («Скажи тьютору: игра не скачалась»), `обнови приложение`;
- точка связи в шапке: «есть связь» или «нет связи»;
- экран «Попроси тьютора» с полем адреса и подсказкой, где тьютор видит адрес;
- обложки через `kibapp://cover/<sha256>` из кеша после проверки хеша, как сейчас;
- IPC: к `catalog.list`, `game.launch`, `vote.send` добавляется `server.setAddress(адрес)` из ADR-0002 4.1 и событие из основного процесса `catalog.changed` без данных (окно заново спрашивает `catalog.list`). Других каналов нет;
- оценки остаются локальными, как на В0 (оценки по сети — М4).

**Сеть на время игры** (К21): пока открыто окно игры, опрос, обнаружение и загрузки остановлены, сокеты закрыты. После закрытия игры сеть возобновляется со случайной задержкой.

**Ошибки по-русски** (ADR-0003, раздел 6): ребёнок не видит технических текстов, тьютор видит причину в окне «О программе» (журнал только в памяти, последние 50 строк). Окно «О программе» открывается из меню знака K1 и показывает название школы, отпечаток группами по 4, адрес сервера, журнал.

**Тест-«взломщик»** (ADR-0002, раздел 7):
- два сетевых пространства, соединённых `veth`: «сервер» (10.99.0.1) и «ученик» (10.99.0.20), плюс адрес «интернета» вне подсети. Проба 03.11.2026: внутри `unshare -Urn` вложенное пространство и `veth` создаются без root;
- `tcpdump` в пространстве ученика, приёмники на сервере, соседе и адресе «интернета»;
- поддельный сервер в тесте (`redteam/fake-server.js`) с режимами подделок для К15, К16, К18;
- для каждого нового критерия — прогон без защиты: если атака без защиты не сработала, тест провален. Без защиты значит, что стенд в `redteam/` подменяет фильтр или проверку на пропускающие (замена функции в загруженном модуле). В рабочем коде нет параметра или ключа, отключающего защиту: проверка поиском строк в `app.asar`.

**Сборки:** `npm run check:builds` дополнительно ищет в `app.asar` ученика `tutor/server`, `createServer`, `powerSaveBlocker` и имена режимов стенда без защиты. Обе программы собираются для Windows папкой и упаковываются `scripts/make-win-zips.js`: у Влада нет Node, проверка на Windows идёт на exe.

## Что не входит

Оценки по сети, `POST /v1/votes`, `GET /v1/ratings` (М4). Докачка, `Range`, слоты, 503, предел скорости, очередь и приоритет по нажатию «Играть», отметка «нужна на занятии», импорт с флешки, предел кеша 5 ГБ (М3). Установщики, правило брандмауэра в установщике, значки (М5). На М2 доступ в сеть программе тьютора разрешает обычное окно Windows при первом включении раздачи. Объединение каталогов нескольких серверов. Изменения витрины сверх перечисленных.

## Порядок работы

1. `shared/netif.js`: подходящие интерфейсы, подсети, проверка адреса, отсев VPN. Тесты С2. Перевод `lanIp()` в `run.js` на этот модуль.
2. `tutor/server.js`: HTTP и UDP, правила отказа, `ETag` и 304, только хеши из каталога. Модульные тесты С7 и серверной части К18.
3. Окно тьютора: раздача, выбор интерфейса, адрес, `powerSaveBlocker`. Тесты С8 (Т12), снимки.
4. Метка школы и режим настроенного ноутбука, отказ посторонним файлам (К19).
5. `desktop/school-net.js`: фильтр, обнаружение, загрузка с пределами, `state.json`, кеш, удаление снятого. Модульные тесты К15, К16, С3–С5 с поддельным сервером на loopback.

## Решения Влада от 03.11.2026

| Вопрос | Решение |
| --- | --- |
| Игры неизвестного автора (`author: null`) | Запускаются на настроенном ноутбуке, вместо автора «Опубликовал тьютор» |

## Уточнения при выполнении

- **Окно «О программе»** сделано как окно «Связь с тьютором»: открывается нажатием на точку связи в шапке («есть связь» / «нет связи»), а не из меню знака K1. В нём школа, отпечаток группами по 4, адрес сервера, поле адреса и журнал для тьютора (последние 50 строк, только в памяти). Отдельного меню у витрины нет, и так ребёнок не попадает в это окно случайно.
- **Метка школы на Windows** читается из `C:\ProgramData\KIBERone Games\school.json`, а не из переменной `ProgramData`: ученик может задать свою переменную с тем же именем и подложить чужую метку. Если Windows стоит не на диске C, ноутбук считается ненастроенным.
- **Ответ на обнаружение** сервер шлёт с сокета на адресе раздачи, а не с общего `0.0.0.0`: иначе при нескольких адресах на интерфейсе ученик получил бы ответ с другого адреса и не смог подключиться. Нашёл тест-«взломщик» (С6, смена адреса сервера).
- **Проверки и фильтр** вынесены в объекты модулей `checks` (`desktop/vitrina/net-source.js`) и `filter` (`desktop/school-net.js`). Рабочий код их не меняет, подменяет только режим `net-control` стенда в `redteam/`. `check:builds` ищет в обеих сборках файлы и строки стенда (`disableProtection`, `REDTEAM_CONFIG`, имена контрольных режимов).
- **IGMP.** Захват в пространстве ученика не считает пакеты IGMP: их шлёт ядро, когда Chromium подписывается на группу mDNS, так же их исключает существующий К4. Других пакетов, кроме запросов к серверу и широковещания подсети, нет.
- **Неудачная загрузка** повторяется при следующем опросе, а не сразу: за один цикл файл пробуется один раз. Обрыв и молчание сервера тоже считаются неудачей и заканчивают цикл.
- **Порядок карточек** в режиме по сети: сначала отмеченные «на этом занятии», потом по названию. Метки «НОВОЕ» на витрине нет: на В0 её тоже не было, витрину сверх каталога по сети не меняю.
- **Состояние «готово»** на карточке не подписывается (как на В0): подпись есть только у недоступных и качающихся игр.
- **`К4` и `К19` на настоящей программе** проверяются запуском `desktop/main.js` в пространстве ученика: без метки 12 с ни одного пакета; с меткой посторонний файл не открывается. Что программа с меткой не читает `trusted-keys.json` и папку `games`, видно из кода `main.js` (с меткой витрина получает только `netSource`), отдельного теста на это нет.
- **Испорченная метка** показывает экран «Ноутбук настроен с ошибкой», сети нет, посторонний файл не открывается. Тест-«взломщик» проверяет это на настоящей программе второй строкой К19 (пакеты и отказ файлу), сам экран — по коду.
