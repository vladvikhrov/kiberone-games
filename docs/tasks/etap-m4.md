# Этап М4: оценки по сети

Постановка к ADR-0002 (разделы 3.4, 3.7, 3.8, 4: У7, У9, У10; раздел 6, правила нагрузки; раздел 7, этап М4) с поправками ADR-0003, раздел 10. Где они расходятся, верен ADR-0003. Этап закрыт, только когда каждый критерий подтверждён запуском. Статус: **согласовано Владом 04.11.2026, выполнено на Linux, ждёт проверки на Windows и занятия (Р6)**, решения по вопросам — в конце. Отчёт: [`otchet-m4.md`](otchet-m4.md).

## Цель

Ребёнок ставит игре от 1 до 5 звёзд, оценка уходит на сервер тьютора, и весь класс видит среднее на карточке и в окне игры. Тьютор видит, сколько каких звёзд получил каждый режим, и может сохранить срез. Имён, ников, адресов и времени голоса нет нигде на диске. Один ноутбук оценивает режим один раз в день: повтор не считается ни в программе ученика, ни на сервере. Голоса не мешают раздаче игр и не нарушают тишину сети, пока идёт игра (К21).

Исходные условия: всё из постановок М2 и М3. Режимы (`modes`, вкладки, `?mode=`, проверки манифеста, `kibpack`) сделаны на В0, `minAppVersion` 1.1.0 у игр с режимами — на М1. Оценки сейчас локальные: `vote.send` пишет `ratings.json` в папку ученика (`store.js`), тьютор читает свой пустой `ratings.json`. Результатов проверки на Windows к началу М4 нет: таблицы `windows-v0.md` … `windows-m3.md` пустые.

## Что входит

**Сервер тьютора** (`app/desktop/tutor/server.js` и новый модуль голосов `desktop/tutor/votes.js`, без Electron):
- **`POST /v1/votes`**. Только этот путь принимает тело. `Content-Type: application/json`, `Content-Length` обязателен, тело до 256 байт, читается с таймаутом 5 с. Больше 256 байт, `Transfer-Encoding`, тело у `GET` — 413, как сейчас. Тело строго `{ "game", "mode", "value" }`, без лишних полей: `game` и `mode` по `^[a-z0-9-]{1,40}$` и только из текущего подписанного каталога, `value` целое 1–5. Поле `key` из ADR-0002 3.4 не нужно: его роль выполняет адрес в HMAC (ADR-0003, 10);
- ответы: `204` принят, `400` неверный JSON, поля, игра или режим не из каталога, `409` этот ноутбук уже оценил режим сегодня, `413` большое тело, `429` переполнена память защиты от повторов (предел 50 000 отметок за день; на классе это не достигается), `403` при `Origin` и `405` на другие методы, как сейчас. Адрес не из подсети отвергается на соединении, как на М2;
- **защита от повторов**: множество `HMAC-SHA256(соль дня, адрес + "\n" + игра + "\n" + режим)` только в памяти. Соль — 32 случайных байта, тоже только в памяти, новая при смене даты по часам ноутбука тьютора и при каждом запуске программы тьютора. Выключение и включение раздачи соль не меняет (см. вопрос 2). Голос, отвергнутый проверкой, отметку не ставит;
- **счётчик**: `ratings.json` в папке данных тьютора в формате ADR-0003, 10 (`shared/ratings.js`, `addVote`), атомарная запись после каждого принятого голоса. Испорченный файл откладывается в `ratings.json.bad-<дата>`, а не затирается. Никаких других файлов модуль голосов не пишет, журнала нет;
- **`GET /v1/ratings`**: `{ "format": 1, "games": { игра: { режим: { "n": 3 } | { "n": 7, "counts": { "1": …, "5": … } } } } }`. При `n < 5` только `n`, распределение не раскрывается. Только игры и режимы текущего каталога. `ETag` по номеру изменения счётчика, поддержка 304. Не подписано (ADR-0002 3.4, У7);
- **дата дня**: заголовок `X-K1-Day: ГГГГ-ММ-ДД` (по часам тьютора) в ответах `/v1/catalog` (200 и 304) и `/v1/ratings`. В подписанный каталог дата не входит: его подписывают один раз при публикации;
- **голоса вне слотов и ведра**: `POST /v1/votes` и `GET /v1/ratings` не занимают слот, не берут токены и не считаются в «качают N · ждут M». Сервер отвечает на голос, даже когда все 3 слота заняты и предел 30 Мбит/с стоит.

**Сеть ученика** (`app/desktop/school-net.js`): `post(ip, path, body)` по тем же правилам, что `get`: фильтр адреса, без DNS и перенаправлений, тело до 256 байт, ответ до 1 КБ, таймаут простоя. `get` возвращает ещё заголовок `X-K1-Day`, если он строго `ГГГГ-ММ-ДД`.

**Ученик** (`app/desktop/vitrina/net-source.js`, `api.js`, `store.js`):
- **очередь голосов в памяти**: `vote(game, mode, value)` ставит голос в очередь, повтор того же режима заменять нельзя. Голос уходит в начале цикла после каталога, до загрузок, и сразу, если сервер на связи и игра не идёт. `204` и `409` убирают голос из очереди, `400` тоже (игру сняли), с записью в журнал. Обрыв, молчание, нет сервера — голос ждёт следующего цикла. Пока идёт игра, сеть остановлена (К21), голос ждёт закрытия игры. При закрытии программы очередь теряется (ADR-0002, «Когда сервер пропал»);
- **дата**: день для правила «одна оценка в день» берётся из `X-K1-Day` последнего ответа сервера, без сервера — по часам ноутбука, как на В0;
- **рейтинг с сервера**: `GET /v1/ratings` в каждом цикле опроса после каталога (с `If-None-Match`), строгая проверка схемы, предел 256 КБ, только игры и режимы принятого каталога. Последний ответ хранится в памяти, на диск не пишется. После отправленного голоса рейтинг запрашивается сразу;
- **на настроенном ноутбуке** `vote.send` больше не пишет `ratings.json` ученика: только отметку дня в `state.json` и голос в очередь. Ноутбук без метки школы работает как на В0, локально;
- витрина принимает те же 4 канала. `vote.send` отвечает `{ ok: true, queued: true|false }`, состояние меняется через событие `catalog.changed`.

**Витрина** (ADR-0003, 2.3, экран 3 макета): после 5 с на отмену — «Спасибо! Оценка ушла тьютору», если голос принят сервером, и «Отправлю, когда будет связь», если он ждёт в очереди. Звёзды и среднее на карточке и в окне игры — с сервера, при `n < 5` «мало оценок · 3 оценки», как сейчас. Без сервера показывается последний полученный рейтинг, до первого ответа — «мало оценок».

**Программа тьютора** (экран 4 макета): панель «Оценки» вместо «Оценки за занятие» (дней больше нет): распределение 5…1 по каждому режиму из `ratings.json`, обновляется вместе с плашкой раздачи раз в 3 с. Подпись «С ноутбуков учеников оценки пока не приходят» убирается, новая: «Оценки без имён и адресов. Один ноутбук оценивает режим раз в день». Кнопка «Сохранить срез»: системное окно сохранения, имя по умолчанию `ocenki-ГГГГ-ММ-ДД.json`, в файл идёт копия `ratings.json`. Новый канал `ratings.saveSnapshot` без аргументов.

**Тест-«взломщик» и стенды** (`app/redteam/`): проверки М4 на настоящем сервере и настоящей программе ученика в сетевых пространствах, ключ `node redteam/run.js --m4`. Контрольные режимы стенда (без HMAC, без проверки каталога, с журналом голосов, без паузы сети) подключаются только из `redteam/`, как `checks` и `filter` на М2: объект модуля голосов, который подменяет стенд. `check:builds`: в сборке ученика нет `votes.js` и строк сервера голосов, в обеих сборках нет контрольных режимов.

**Сборки:** обе программы для Windows папкой, архивы `scripts/make-win-zips.js`, задание `windows-m4.md` с таблицей результата.

## Что не входит

Рейтинг учеников, ники, очки, статистика запусков. Счётчики по дням и удаление дня (ADR-0003, 10: вместо этого «Сохранить срез»). Потолок голосов на окно (отменён ADR-0003, 10). Сортировка витрины по оценкам. Подпись или шифрование голосов и рейтинга (У7 принят). Хранение очереди голосов на диске. Установщики, значки, брандмауэр (М5). Изменения витрины сверх перечисленных.

## Уточнения при выполнении

- **Коды ответа.** Кроме 204, 400, 409, 413, 429 сервер отвечает 411 на голос без `Content-Length` и 415 на тело не `application/json`. `GET /v1/votes` — 405. Сервер без модуля голосов (как на М2 и М3) отвечает 404 и на `/v1/votes`, и на `/v1/ratings`.
- **409 у ученика считается доставкой.** Голос убирается из очереди, витрина пишет «Оценка ушла тьютору». Так бывает, только если ребёнок удалил `state.json` или программа ученика переустановлена: голос в счётчик не попал, а объяснять это ребёнку незачем.
- **`vote.send`** отвечает `{ ok: true, net: true, game }`. Идёт ли голос ещё в очереди, витрина узнаёт из `catalog.list` (поле режима `votePending`) после события `catalog.changed`, отдельного ответа `queued` нет. Каналов по-прежнему 4.
- **Звёзды остаются залитыми после отправки.** Раньше после отправки они гасли: ребёнок не видел, что поставил. Нашёл по снимку стенда.
- **Рейтинг игры на карточке** считает сервер (поле `n` и `counts` у игры в ответе `/v1/ratings`), а не витрина: витрина не может сложить режимы, у которых распределение скрыто.
- **Р1 проверяется только модульными тестами.** Часы Electron в стенде не подменить без подмены кода. Тест: ученик с часами на день вперёд берёт дату тьютора из `X-K1-Day`, кривой заголовок отбрасывается.
- **Р3** — модульный тест через API программы тьютора (голоса видны в `state.get` без перезапуска, срез побайтно совпадает по содержимому) и снимки панели. Живое окно тьютора с голосами по сети не гоняется: стенд снимков не может открыть сокет на примерном адресе, а обновление панели — тот же опрос `state.get`, что у плашки М3.
- **К29 на стенде нагрузки** проверяется внутри сценария Н2: на 10-й секунде, при занятых слотах и пределе 30 Мбит/с, голосуют все 15 ноутбуков. Контроль (большой файл в это время получает 503, значит слоты полны) — в модульном тесте, на стенде — то же по числу ответов 503.
