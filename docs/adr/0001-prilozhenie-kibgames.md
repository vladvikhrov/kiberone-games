# ADR-0001: Приложение для Windows, которое запускает игры из файлов .kibgames

**Статус:** предложено
**Дата:** 01.11.2026
**Решают:** Влад, Кирилл

## Контекст

Сейчас игры лежат папками в `kiberone-games/`, а запускаются через `index.html` или `pult.py`. Для коллег это неудобно: нужно копировать папки, для сети нужен Python и терминал, новую игру приходится вручную вписывать в меню.

Нужно приложение `.exe`: тьютор дважды щёлкает по файлу `.kibgames`, игра появляется в библиотеке и запускается на ПК.

### Требования

**Что делает приложение**
- Устанавливается на Windows 11 без навыков программирования.
- Открывает `.kibgames` двойным щелчком, перетаскиванием и кнопкой.
- Показывает библиотеку игр: название, класс, длительность, тема, автор, версия.
- Запускает игру на весь экран, обновляет и удаляет игры.
- Работает без интернета.

**Безопасность**
- Игра не может выйти в сеть, прочитать файлы компьютера или другую игру.
- Приложение не собирает и не отправляет данные: нет аналитики, аккаунтов и автообновления.
- Видно, кто автор игры и менялась ли она после подписи.

**Ограничения**
- Масштаб маленький: десятки ПК, единицы и десятки игр, файл игры до нескольких мегабайт. Сервер и база не нужны.
- Разрабатывают два тьютора, разработка идёт на Linux, игры написаны на HTML/JS.
- Игры уже существуют, и переписывать их не хочется.

### Что нашлось в текущем коде

| Находка | Где | Почему важно |
| --- | --- | --- |
| Сейф загружает шрифты с Google Fonts | `vzlomai-seif/index.html:4` | При каждом запуске IP ученика уходит на внешний сервер. README при этом обещает работу офлайн. В приложении запрос заблокируется, и шрифт сменится на запасной, поэтому шрифты нужно положить в папку игры |
| Список игр в меню записан вручную | `index.html:27` | В приложении его заменит библиотека, собранная из манифестов |
| Сервер пульта слушает всю сеть без пароля | `pult.py:165` | Игры видны любому устройству в той же сети. Для школьного Wi-Fi это нужно учесть при переносе (см. этап 5) |
| `pult.py` и правки игр не закоммичены | `git status` | Закоммитить до начала работы над приложением |

## Решение

Делаем приложение на **Electron**. Файл `.kibgames` — это ZIP с манифестом и подписью Ed25519. Каждая игра работает в отдельной песочнице без доступа к сети и диску. Режим раздачи по сети переносим из пульта отдельным этапом, по умолчанию он выключен.

## Рассмотренные варианты

Размеры приблизительные, их нужно уточнить на первой сборке.

### A. Electron (выбран)

| Критерий | Оценка |
| --- | --- |
| Сложность | Средняя |
| Цена | Бесплатно, установщик около 100 МБ |
| Масштаб | С запасом для задачи |
| Знакомство команды | Высокое: тот же JavaScript, что в играх |

**Плюсы:** своя версия Chromium, поэтому игры ведут себя одинаково на всех ПК. Сетевые запросы можно перехватывать на уровне сессии, а не только через CSP. Запускается на Linux, поэтому основную часть можно отлаживать без Windows. Есть готовая сборка установщика с привязкой расширения файла.

**Минусы:** большой размер. Движок нужно обновлять самим, выпуская новые версии приложения.

### B. Tauri

| Критерий | Оценка |
| --- | --- |
| Сложность | Выше: основная часть на Rust |
| Цена | Бесплатно, установщик около 10 МБ |
| Масштаб | С запасом для задачи |
| Знакомство команды | Низкое |

**Плюсы:** маленький файл. Движок WebView2 обновляет Windows.

**Минусы:** Rust придётся поддерживать двум тьюторам. Версия движка зависит от конкретного ПК. Запрет сети держится в основном на CSP.

### C. Python, pywebview и PyInstaller

| Критерий | Оценка |
| --- | --- |
| Сложность | Низкая на старте |
| Цена | Бесплатно, 20–40 МБ |
| Масштаб | С запасом для задачи |
| Знакомство команды | Высокое, можно взять код из `pult.py` |

**Плюсы:** быстрый старт.

**Минусы:** антивирусы часто ложно срабатывают на PyInstaller, а для приложения, которое раздают коллегам, это серьёзная проблема. Меньше средств изоляции игры.

### Почему Electron

Главное требование здесь — изоляция при небольшой поддержке, а не размер файла. 100 МБ передаются один раз через флешку или мессенджер. Если размер станет проблемой, формат `.kibgames` останется прежним и менять придётся только оболочку.

## Устройство

```
 .kibgames ──► Основной процесс Electron
               ├─ Импорт: проверка ZIP, манифеста, подписи
               ├─ Библиотека: %APPDATA%\KIBERone Games\
               ├─ Протокол kibgame://: отдаёт файлы прямо из ZIP
               └─ Сетевой фильтр: всё, кроме своих протоколов, отклоняется
                     │                         │
              узкий IPC                  только kibgame://<id>/
                     ▼                         ▼
              Окно библиотеки            Окно игры (песочница)
              kibapp://ui/               без Node, без IPC, без preload,
                                         своя сессия в памяти
```

Игры не распаковываются на диск. Файлы читаются из ZIP, и хеш каждого сверяется с манифестом при чтении, поэтому подмену файла после установки приложение заметит.

### Формат .kibgames

```
kiberpochta.kibgames     (обычный ZIP)
├─ manifest.json
├─ manifest.sig          подпись Ed25519 точных байтов manifest.json
├─ icon.png
└─ game/
   ├─ index.html
   └─ ...
```

```json
{
  "format": 1,
  "id": "kiberpochta",
  "version": "1.2.0",
  "title": "Киберпочта",
  "description": "Отличить настоящее сообщение от ловушки мошенников",
  "authors": ["Влад"],
  "grades": "4–5 класс",
  "minutes": 30,
  "topic": "Кибербезопасность",
  "entry": "game/index.html",
  "minAppVersion": "1.0.0",
  "publicKey": "…",
  "files": { "game/index.html": "sha256:…" }
}
```

В манифесте намеренно нет поля разрешений. Игра не может попросить больше доступа, потому что такого механизма не существует.

### Проверки при импорте

Проверки идут до показа карточки игры. Любая ошибка отменяет импорт и выводит понятное сообщение на русском.

1. Размер файла, число записей и суммарный размер после распаковки в пределах лимита (защита от ZIP-бомб). Начальные лимиты: 200 МБ и 5000 файлов.
2. Каждый путь относительный, без `..`, без абсолютных путей, символических ссылок и дублей.
3. Манифест проходит проверку схемы, `id` соответствует `^[a-z0-9-]{1,40}$`.
4. Список файлов в ZIP совпадает с `files` один к одному, лишних файлов нет, хеши верны.
5. Подпись проверяется по ключу `publicKey` из манифеста, затем ключ ищется в списке доверия школы.
6. Если `id` уже установлен, новый файл должен быть подписан тем же ключом. Старая версия ставится только после отдельного подтверждения.

### Подпись и доверие (пересмотрено 01.11.2026: игры могут делать любые авторы и другие школы)

Встроенный список из двух ключей не подходит: любой автор должен иметь возможность выпустить игру, а школа должна сама решать, кому доверять.

- Любой автор создаёт свой ключ через `kibpack keygen`. Публичный ключ лежит в манифесте (`publicKey`), поэтому файл проверяется без интернета. Игра без подписи не устанавливается никогда.
- Подпись доказывает две вещи: файл не менялся и его выпустил владелец ключа. Она **не** доказывает, что автор тот, кем назвался: в поле `authors` можно написать что угодно. Поэтому имя автора показывается как «называет себя», пока ключа нет в списке доверия.
- У каждой школы свой список доверенных ключей с именами, которые задаёт администратор школы. Для ключа из списка показывается имя из списка, а не из манифеста.
- Игра неизвестного автора ставится только после явного предупреждения с отпечатком ключа. Песочница у всех игр одинаковая.
- Обновление принимается только с тем же ключом, которым подписана установленная версия.

Приватные ключи не лежат в репозитории, `kibpack keygen` откажется создавать ключ внутри git-репозитория. Потерянный ключ означает, что обновление придётся ставить как новую игру. Украденный ключ школа удаляет из своего списка.

Общего онлайн-каталога пока нет: игры передаются файлом. Каталог потребовал бы сервера и модерации, это отдельное решение.

### Песочница игры

| Угроза | Защита |
| --- | --- |
| Доступ к файлам и системе | `sandbox: true`, `nodeIntegration: false`, `contextIsolation: true`, нет preload и IPC |
| HTTP, WebSocket, картинки и шрифты извне | Отказ в `session.webRequest` для всего, кроме `kibgame://<свой id>/`. Плюс CSP в заголовке каждого ответа |
| WebRTC, который `webRequest` не видит | Политика `disable_non_proxied_udp` и нерабочий прокси на сессии игры. **Проверить тестом** |
| Переход на сайт, новое окно, скачивание | Запрет в `will-navigate` и `setWindowOpenHandler`, отмена в `will-download` |
| Камера, микрофон, геолокация, буфер, USB | `setPermissionRequestHandler` и `setPermissionCheckHandler` всегда отказывают |
| Чтение данных другой игры | Отдельный origin `kibgame://<id>` и отдельная сессия |
| Следы на диске | Сессия без префикса `persist:`, данные живут в памяти. `sessionStorage` переживает F5 и исчезает с закрытием окна, как сейчас |
| Подмена самого приложения | Electron Fuses: выключить `RunAsNode`, `NODE_OPTIONS` и отладку, включить проверку целостности ASAR |

Заголовок CSP для игр:

```
default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:; font-src 'self' data:; media-src 'self' data: blob:;
connect-src 'self'; form-action 'none'; base-uri 'none'; frame-ancestors 'none'
```

`unsafe-inline` нужен, потому что Сейф написан одним файлом со встроенным кодом. Запрет сети от этого не слабеет.

### Что значит «без утечек»

Приложение само не делает ни одного сетевого запроса: нет телеметрии, автообновления и отчётов об ошибках. Журнал ошибок лежит локально, без имён и данных учеников.

Песочница не проверяет **содержимое** игры. Игра может показать неправильный текст или попросить ребёнка ввести личные данные, хотя передать их никуда не сможет. Эту проблему решает только подпись: устанавливаются игры от известных авторов.

│ ┌───────────────┐ ┌───────────────┐ ┌ ─ ─ ─ ─ ─ ─ ─ ─ ┐ │

Цвета берём из текущего меню. Перед установкой показывается карточка с названием, автором и версией и кнопками «Установить» и «Отмена». Игра открывается на весь экран. Выход через Esc с подтверждением, чтобы ученик не закрыл игру случайно и не потерял прогресс.

### Инструмент для авторов: kibpack

Консольная программа на Node в этом же репозитории:

```bash
kibpack keygen                         # создать пару ключей вне репозитория
kibpack pack kiberpochta/ --key <ключ> # собрать и подписать .kibgames
kibpack verify kiberpochta.kibgames    # выполнить те же проверки, что и приложение
```

При сборке `kibpack` предупреждает о внешних ссылках в HTML и CSS: такую проблему, как с Google Fonts, автор увидит сразу. Проверку использует и приложение, и `kibpack`, код один.

### Сбои

| Ситуация | Поведение |
| --- | --- |
| Файл повреждён или не прошёл проверку | Импорт отменяется, сообщение объясняет причину, библиотека не меняется |
| Файл в библиотеке изменён или испорчен | Карточка помечается, запуск запрещён, предлагается установить заново |
| Открыт второй `.kibgames` при запущенном приложении | Единственный экземпляр приложения принимает файл и показывает карточку импорта |
| Игра зависла | В окне игры работает выход, остальное приложение не затронуто |

## Компромиссы

- **Размер в обмен на контроль.** Установщик в 10 раз больше, чем у Tauri, зато изоляция и поведение одинаковы на всех ПК.
- **Открытость в обмен на проверку людьми.** Игру может выпустить кто угодно, поэтому её содержимое никто заранее не проверил. Песочница защищает компьютер и не даёт данным уйти, а решение о том, подходит ли игра детям, остаётся за школой и её списком доверия.
- **Нет автообновления.** Новые версии раздаём вручную. Зато приложению вообще не нужна сеть, но устаревший Chromium становится нашей заботой. Риск снижает то, что приложение открывает только подписанные игры и не ходит в интернет.
- **Нет подписи кода Windows на старте.** SmartScreen покажет предупреждение о неизвестном издателе, на управляемых компьютерах установку может запретить администратор. Покупать сертификат стоит, только если это реально помешает.

## Последствия

**Станет проще:** раздавать игры одним файлом, обновлять их, запускать без Python и терминала, обещать родителям и школе, что данные никуда не уходят.

**Станет сложнее:** выпуск игры теперь требует сборки и подписи, а выпуск приложения — сборки под Windows. На Linux без Windows финальную проверку не сделать.

**Вернуться к решению, если:** понадобится общий онлайн-каталог игр, понадобится рейтинг из этапа 2 (игре потребуется контролируемый API для передачи результатов), нужны будут macOS или Chromebook.

- [x] **Этап 1. Формат.** Общий модуль проверки и `kibpack` с тестами на ZIP-бомбу, выход из папки, подмену файла, неверную подпись.
- [x] **Этап 2. Песочница** (результат: `docs/tasks/etap-2-pesochnitsa.md`). Оболочка Electron и тестовая игра-«взломщик», которая пытается сделать `fetch`, WebSocket, WebRTC, загрузить картинку извне, перейти на сайт, открыть окно, прочитать `file://` и данные другой игры. Сеть проверяется снаружи, например через `tcpdump`: не должно быть ни одного исходящего пакета. Без этого теста этап не считается законченным.
- [ ] **Этап 3. Интерфейс.** Библиотека, импорт, запуск, удаление, обновление.
- [ ] **Этап 4. Сборка под Windows.** Установщик без прав администратора и привязка `.kibgames`, сборка через GitHub Actions на Windows. Проверка на реальном школьном ноутбуке, включая антивирус и SmartScreen.
- [ ] **Этап 5. Раздача по сети.** Приложение стоит на всех ноутбуках (решение от 01.11.2026). Вкладка «Класс» у тьютора раздаёт подписанные файлы `.kibgames`, а не страницы. Приложение ученика скачивает файл, проверяет его и запускает в своей песочнице, поэтому защита на ноутбуке ученика та же, что и при локальном запуске. Раздача выключена по умолчанию. Сеть использует только основной процесс и только адреса локальной сети, по коду класса; окна игр остаются без сети. Правило брандмауэра добавляет установщик: у администратора есть права на все ноутбуки.
