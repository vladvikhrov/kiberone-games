# Игры KIBERone: приложение

Из этого кода собираются две программы:

- **«Игры KIBERone»** для учеников: открывается на витрину «K1 Игры» и запускает игры в песочнице: без сети, без доступа к файлам и устройствам, без следов на диске. Без метки школы игры берутся из папки и сети нет совсем. С меткой школы (этап М2) — только из каталога школы по локальной сети;
- **«KIBERone Сервер»** для тьютора (этапы М1, М2): ключ школы, публикация игр, подписанный каталог, раздача в локальной сети. Код в `desktop/tutor/`, в сборку ученика он не входит.

Архитектура: `../docs/adr/0001-prilozhenie-kibgames.md`, маркетплейс: `../docs/adr/0002-marketplace.md`, витрина: `../docs/adr/0003-vitrina.md`.

Нужен Node 22.12 или новее.

## Как выпустить игру

В папке игры должен лежать `kibgame.json` (пример: `../games/kiberpochta/kibgame.json`).

```bash
npm run kibpack -- keygen vlad
npm run kibpack -- pack ../games/kiberpochta --key ~/.config/kibgames/keys/vlad.key.pem
npm run kibpack -- verify kiberpochta-1.0.0.kibgames
```

Обложка и режимы в `kibgame.json` необязательны, пути пишутся от папки игры:

```json
"cover": "cover.png",
"modes": [
  { "id": "training", "title": "Тренировка", "about": "С подсказками", "cover": "cover-training.png" },
  { "id": "exam", "title": "Экзамен", "entry": "exam.html" }
]
```

Обложка только PNG или WebP до 512 КБ, лучше 1280 × 800. Окно игры показывает её полосой 3 : 1 по центру, поэтому главное держите в полосе от 200 до 600 px по высоте. Режимов от 1 до 12, `id` латиницей, цифрами и дефисом. Режим получает свой `id` в адресе страницы: `?mode=training`. Пример: `testgames/tri-rezhima/`.

Закрытый ключ нельзя никому передавать и класть в репозиторий. При его потере обновления игр придётся ставить как новые игры, поэтому сделайте резервную копию.

Школа отмечает авторов, которым доверяет, в файле `%APPDATA%\Игры KIBERone\trusted-keys.json`: `{ "отпечаток ключа": "Имя" }`. Отпечаток показывает `kibpack verify`. Игры остальных авторов запускаются только после предупреждения.

## Витрина

Без файла в аргументах приложение открывает витрину. Игры берутся из `%APPDATA%\Игры KIBERone\games\`, каждая проверяется так же, как при запуске файла. Игры авторов не из `trusted-keys.json` видны с меткой «автор не проверен», запустить их с витрины нельзя. Оценки пишутся в `ratings.json`, отметка «сегодня уже оценил» в `state.json` в той же папке данных.

Код: `desktop/vitrina/` (окно, IPC, каталог, хранилище) и `desktop/vitrina/ui/` (страница, стили, шрифты Golos Text и JetBrains Mono под OFL). Логика оценок: `shared/ratings.js`.

## Программа тьютора

Данные лежат в `%LOCALAPPDATA%\KIBERone Server\` (на Linux `~/.local/share/KIBERone Server/`):

| Файл | Что в нём |
| --- | --- |
| `school-key.enc` | Закрытый ключ школы Ed25519, только зашифрованный: копия под паролем и копия под кодом восстановления (scrypt N = 2^17, AES-256-GCM) |
| `school.kibschool` | Название школы, открытый ключ и отпечаток. Секрета нет, этот файл ставится на ноутбуки учеников |
| `login.json` | Счётчик ошибок входа: задержка растёт до 60 с и не сбрасывается перезапуском |
| `catalog.json` | Подписанный каталог `{ payload, sig }`: подпись Ed25519 над `kibcatalog-v1\n` + содержимое. Это и есть список игр школы |
| `blobs/<sha256>` | Файлы опубликованных игр и их обложки, без расширения |
| `trusted-keys.json` | Список доверия школы: `{ "отпечаток ключа автора": "Имя" }` |
| `ratings.json` | Оценки в формате ADR-0003, раздел 10. На этапе М1 их сюда никто не присылает |

Через 10 минут без нажатий мыши и клавиш ключ в памяти затирается и программа просит пароль снова.

**Раздача** (этап М2, `desktop/tutor/server.js`): выключена при каждом запуске, тьютор включает её на плашке «РАЗДАЧА УЧЕНИКАМ» и выбирает сеть. VPN и виртуальные адаптеры в списке не показываются (`shared/netif.js`). Сервер только читает: `GET /v1/catalog` (`ETag` = `seq`, ответ 304) и `GET /v1/blobs/sha256/<hex>` для файлов из текущего каталога, порт 47800, TCP и UDP. Отвечает только адресам своей подсети, отвергает запросы с `Origin`, журнала запросов не ведёт. Работает и при закрытом ключе, пока включена — ноутбук не засыпает. Правило брандмауэра программа не создаёт: при первом включении Windows сама спросит про доступ к сети.

**Нагрузка на сеть** (этап М3, ADR-0002, раздел 6): одновременно отдаются не больше 3 файлов больше 1 МБ, по одному на ноутбук, остальным `503` с `Retry-After` (через сколько секунд освободится слот, 2–60 с). Каталог и мелкие файлы идут вне очереди. Все файлы вместе — не быстрее 30 Мбит/с, кнопка «Скачать быстрее» на плашке снимает предел до выключения раздачи. На плашке видно, сколько ноутбуков качают и сколько ждут, без адресов. `Range` и `If-Range` (`ETag` — хеш файла) для докачки. Кнопка «На этом занятии» ставит игру первой на витрине и велит ноутбукам скачать её заранее при любом размере (`prefetch` в каталоге).

## Настроенный ноутбук ученика (этапы М2, М3)

Метка школы — файл `school.kibschool` из программы тьютора, скопированный администратором в `C:\ProgramData\KIBERone Games\school.json` (на Linux `/etc/kiberone-games/school.json`). Команды и права папки — в `../docs/tasks/windows-m2.md`. Из исходников: `npx electron . --school=файл --local-data=папка`.

С меткой программа:
- ищет сервер: последний рабочий адрес, затем UDP на широковещательные адреса школьных сетей, через 15 с без каталога — экран «Попроси тьютора» с полем адреса;
- принимает каталог, только если он подписан ключом из метки и его `seq` не меньше сохранённого;
- качает обложки игр, обложки режимов, затем игры, по одному файлу; кладёт в кеш только файл с `sha256` и размером из каталога и игру, подписанную ключом автора из каталога;
- сама качает только игры до 20 МБ и отмеченные тьютором «На этом занятии». Остальные — по кнопке «Играть»: игра встаёт первой, другие загрузки на паузе, на кнопке процент и примерное время. Докачавшись, игра сама не запускается (М3);
- оборванная загрузка остаётся в `cache\<sha256>.part` и продолжается с места обрыва (`Range`), после загрузки файл проверяется целиком. Повторы через 5, 10, 20, 40, 60 с со сдвигом ±30 %. «Не скачалась» ставят только 3 неудачные проверки, обрыв связи — нет;
- кеш не больше 5 ГБ и не меньше 2 ГБ свободного места на диске. Если места нет, само ничего не качается, а «Играть» убирает игры не с этого занятия, которые дольше всего не запускались. Не помогло — «мало места»;
- запускает игру из кеша после новой проверки, на время игры останавливает всю сеть;
- не открывает посторонние `.kibgames`, не читает `trusted-keys.json` и папку `games`.

| Файл | Что в нём |
| --- | --- |
| `%LOCALAPPDATA%\KIBERone Games\catalog.json` | Последний принятый каталог |
| `%LOCALAPPDATA%\KIBERone Games\state.json` | `seq`, последний адрес сервера, когда запускалась каждая игра |
| `%LOCALAPPDATA%\KIBERone Games\cache\<sha256>` | Игры и обложки. Снятые игры удаляются при новом каталоге |
| `%LOCALAPPDATA%\KIBERone Games\cache\<sha256>.part` | Недокачанное. Удаляется через 7 дней и при снятии игры |

Вся сеть программы ученика — в `desktop/school-net.js` (Node `http` и `dgram`, только IPv4 своей подсети, без DNS и перенаправлений). Логика каталога и кеша — `desktop/vitrina/net-source.js`. Проверка каталога для программы ученика (этап М2): `shared/catalog.js`, функция `verifyCatalog`. Подпись: `desktop/tutor/catalog-sign.js`.

Проверки М3: `node redteam/run.js --m3` (подмена при докачке с контрольным прогоном, «Играть» в настоящей витрине), `node redteam/load-run.js` (15 учеников, 20/50/150 Мбит/с, около 10 минут; `--quick` — только 50 Мбит/с), `node redteam/big-game.js` (запуск игры на 200 МБ: время, память, перемотка звука).
